# MiniProctor -- постановка задачи

## Контекст и цель

Пет-проект по ML для портфолио. Цель трудоустройства -- попасть в команду, которая разрабатывает ПО для приёмки экзаменов в вузах и обучающих организациях. Проект в домене будущей команды сильно повышает шансы.

Владелец проекта -- Валентюк Евгений Григорьевич. По текущему опыту -- системный/бизнес-аналитик, профиль СА «не при чём», готов развиваться в ML. Python на старте -- минимальный, основной способ работы -- vibe-coding через Claude Code.

## Исходные вводные

- **Цель:** портфолио/резюме, не коммерческий продукт.
- **Срок:** плотная неделя.
- **Глубина:** «обучить модель и показать метрики» -- до сервиса с продовым API не доводим.
- **Домен:** обучение, экзамены, прокторинг, машинное зрение, наблюдение за экзаменуемым.

## Проект: Mini-Proctor -- MVP системы прокторинга

Что делает: принимает видео с вебки, находит нарушения, выдаёт таймлайн событий и сводные метрики.

### Детекторы (все на готовых моделях)

1. **Head pose / gaze** -- MediaPipe Face Mesh → углы поворота головы. Флаг «отвёл взгляд» если yaw/pitch за порогом дольше N секунд.
2. **Multi-face** -- если в кадре больше одного человека (подсказчик).
3. **Отсутствие в кадре** -- нет лица → флаг.
4. **Запрещённые предметы** -- YOLOv8 pretrained на COCO ловит `cell phone`, `book`, `laptop`. Плюс fine-tune на своём мини-датасете (100–300 размеченных кадров). Здесь появляется настоящий ML.
5. **Face verification** -- опционально. `face_recognition` / InsightFace сверяет лицо с «эталоном» в начале сессии.

### Стек

- Python + OpenCV + MediaPipe + Ultralytics (YOLOv8) + Streamlit для UI.
- Roboflow -- разметить датасет телефонов/шпаргалок за час. Альтернативы без облака: CVAT, LabelImg.

### Что показать в портфолио

- Таблица метрик по каждому детектору: precision, recall, F1 на тестовом видео, которое записано и размечено самим (30–60 минут «экзамена» с подстроенными нарушениями).
- Confusion matrix для fine-tuned YOLO: до и после дообучения (mAP@0.5).
- Таймлайн событий в Streamlit: видео + шкала с цветными метками нарушений.
- README с архитектурой (C4 -- конёк автора), описанием порогов, допущений, ограничений.
- Раздел «что дальше»: retraining loop, активное обучение, борьба с false positive.

## Почему это сильно для найма в команду прокторинга

- Домен один в один -- в разговоре с нанимающим можно сразу говорить их языком: «ложные срабатывания», «пороги», «сценарии нарушений».
- Есть и классика CV (MediaPipe, OpenCV), и современный детектор (YOLOv8), и реальный fine-tune с метриками.
- Виден цикл: данные → разметка → обучение → метрики → UI → выводы. Это именно то, что делает ML-команда.

## Решения по открытым вопросам (2026-04-15)

- **Датасет для fine-tune YOLO** -- гибрид: база из Roboflow Universe, телефоны и книги, плюс 50–100 своих кадров с вебки для доменной адаптации. В резюме: «использовал открытый датасет + собрал доменный add-on».
- **Сценарий тестового видео** -- суммарно 15–20 минут, короткими клипами по сценариям, не одним дублем. Нарушения:
    1. телефон в руке или на столе -- 2–3 эпизода по 10–20 секунд;
    2. шпаргалка или книга в кадре -- 2 эпизода;
    3. отвод взгляда вбок или вниз дольше 3 секунд -- 3–4 эпизода;
    4. уход из кадра -- 1–2 эпизода по 5–15 секунд;
    5. второй человек в кадре -- синтетически, вклейкой кадра с чужим лицом, так как записать живьём не с кем;
    6. чистый фон без нарушений -- фоновая масса времени для замера false positive.
- **Ground truth** -- CSV с колонками `start_sec, end_sec, event_type`, по этой разметке считаем precision/recall и F1 по каждому детектору.
- **Артефакты обучения** -- локально в `data/` и `models/`. GitHub Releases и HuggingFace Hub откладываем, пока проект не зальём на GitHub.
- **GitHub** -- заливаем позже, в День 7 по плану, когда будет готово демо и метрики.
- **Англоязычный README** -- откладываем до момента заливки на GitHub.
